## A core count that is not one number

Fourteen cores and twenty threads is a strange thing to read on a box with an i5 on it. Intel placed the Core i5-13600KF in its high tier for 2022, and those two figures are only legible together, because desktop silicon of this Alder Lake generation does not contain one kind of core. Some of them exist for work that has to finish quickly; others exist to absorb a great many small tasks cheaply. A count of fourteen treats the two as interchangeable, which is precisely how a spec line becomes misleading.

| What the design separates | What each part is for |
| --- | --- |
| The fast cores | Latency-sensitive work: the part of a frame that has to complete before the next one can begin |
| The smaller cores | Parallel and background load: encoding, capture, the operating system, everything else alive on a desktop |
| The combined total | Throughput, which a program has to be written to reach |

## Why a game may not see the twenty

Software that knows how to use a heterogeneous processor can put background work on the small cores and leave the responsive work on the fast ones. Software that does not simply sees a pool of threads and hopes for the best. A port written for an arbitrary mix of machines, in an engine whose simulation has a serial spine, is not guaranteed to spread itself across all twenty in a way that matters. Console developers do not have that problem. Every unit of this generation that shipped carries the same eight-core Zen 2 design, the same RDNA 2 graphics and the same 16 GB of unified GDDR6, at clock speeds that never vary from machine to machine.

The deeper point is that a larger thread total is not a larger allowance. It is a different shape of machine, and shape only pays off when the workload matches it.
